# B站字幕提取器 Lite 1.2.0

基于 [DFameMaster/bilibili-transcript](https://github.com/DFameMaster/bilibili-transcript) 的本地修改版。保留原作者信息与 MIT 声明；运行时不引入第三方框架或依赖。

## 安装

打开 `bilibili-transcript.user.js`，将全部内容替换到篡改猴／脚本猫中现有的脚本，保存并刷新 B 站视频页。只启用一个版本。

## 1.2.0：批量保存到命名文件夹

操作顺序：批量下载 → 勾选视频 → 开始下载 → 输入文件夹名称 → 确定 → 选择保存位置。脚本会在选择的位置新建该名称的文件夹，将选中的字幕逐个写入；不再产生一批分散的浏览器下载。

名称不预填，必须手动输入；取消命名会回到视频选择。取消系统目录选择或拒绝授权可以重试。已有同名文件夹时要求换名，不合并覆盖；文件名重复时追加序号。单文件下载保持原样。

目录保存使用 [File System Access 的目录选择接口](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)，需支持该接口的 Chrome/Edge，并在系统弹窗中允许写入。脚本不能静默指定系统下载目录；不支持该接口时会显示说明，不会退回散文件下载或悄悄生成 ZIP。

新增测试用模拟目录句柄验证命名顺序、空名称与非法路径拦截、取消、权限拒绝、同名目录保护，以及两条字幕写入同一目录和重名文件处理。尚未在实际篡改猴／脚本猫沙箱里操作系统目录选择器，需实际浏览器确认权限兼容性。

## 1.1.0 的改动

- 主窗口使用原生分 P、字幕语言选择器，保留搜索导航、点击字幕跳转、复制、下载及批量操作。BV、CID、时长移到设置的“详细信息”。
- 主窗口采用固定头尾和字幕滚动区。保留 A 版深色文字、暖色选中背景及明确边框；适配窄屏。
- 删除整套自定义下拉菜单、背景模糊、字幕横移、按钮缩放、通用 `transition: all`、大部分装饰 SVG 和旧 CSS。样式限定在工具自身，避免修改 B 站的 `:root`。
- 搜索 200ms 防抖，中文输入法组词时暂停。搜索预先缓存的小写文本，并更新既有行的状态和文字高亮；搜索与清空不会重建整个字幕列表。正文使用文本节点，搜索特殊字符不会被当作正则或 HTML 执行。
- 每个字幕列表仅一个点击监听，滚动监听为 passive；主窗口事件使用 AbortController 清理。关闭窗口、切 P、切语言会废弃旧搜索／定位任务；异步字幕结果不能覆盖较新的选择。
- 500 条以内一次渲染；超过 500 条先渲染 200 条，滚动或“加载更多”再追加 200 条。搜索覆盖完整数据，远处匹配分批加载后定位；已加载很多条时，高亮更新也每 200 条让出执行时间。复制、下载始终使用完整字幕数据。
- 设置和下载保留自定义扩展名、文件名选项、时间选项和下载方式。下载窗口可直接选格式。批量保留全选、取消全选、完整标题、选中状态与计数。
- 统一弹窗关闭后的滚动恢复；修复恢复默认设置未持久保存的问题；阻止重复点击启动同一批下载，并报告成功／未完成数量。

## 业务边界与独立修复

`request`、`getVideoInfo`、`getVideoPages`、`resolveVideo`、两种字幕列表请求、字幕正文获取、排序、失配检查、`handleDownload` 与原有八个格式转换函数保持不变，测试逐函数对照 `v1.0.2`。缓存与请求去重实现、API 地址、Cookie/Referer、CID 策略、重试参数和 500ms 路由检测保持原样。

本版对导出行为有两项明确修正：

1. 新增明确的 Markdown 转换，使用换行和转义保存原文，避免 Markdown 符号被解释为格式。
2. HTML 统一输出转义正文的完整 HTML 文档；批量 HTML 不再退回 TXT。

没有增加登录绕过、网络接口重构或新的字幕获取来源。

## 验证

测试使用 Edge 无头浏览器和模拟 GM 请求，不连接真实 B 站接口。已验证：

- 单视频、P1/P9/P10 和 SPA URL 切换；语言请求与分 P 切换竞态；连续 20 次切换、20 次关闭重开。
- 搜索防抖、中文输入、特殊字符、清空搜索、行节点保留、5000 条数据末尾定位及旧搜索取消。
- 字幕容器只有一个点击监听，行上无独立点击监听，无 `document` 点击监听累积；点击播放只触发一次。
- 设置保存、恢复默认、自定义扩展名增删、详细信息、嵌套弹窗滚动锁恢复。
- TXT/MD/CSV/XML/HTML/SRT/VTT/ASS/LRC/JSON 的单文件与批量导出；分 P 文件名和选中数量。
- 无字幕、视频信息接口错误、关闭时仍有请求等状态；360px 宽度布局与桌面截图检查；无浏览器脚本异常。

一次本机测试（含强制布局）的首次渲染耗时：100 条约 3ms，500 条约 17ms；1500/5000 条因首批仅 200 条，约 4ms。该数字是模拟数据的局部测量，不是 B 站视频播放帧率、CPU 或 GPU 的测量，也不是跨设备保证。

### 运行测试

需要 Node.js 和 Edge：

```powershell
npm install
npm test
```

Playwright 只用于开发测试，不进入 userscript。若已安装 Playwright，可设置 `PLAYWRIGHT_MODULE` 为其模块目录；`BROWSER_CHANNEL` 默认 `msedge`，可改为已安装的 `chrome`。业务基线测试需要 Git 标签 `v1.0.2`。

## 尚未验证与限制

- 尚未在已登录的真实 B 站视频页验证字幕提取、播放帧率和 CPU/GPU 占用；API 授权、接口变化等仍受 B 站约束。
- 分批追加缓解首次加载和长任务，但不是虚拟列表：浏览完整份超长字幕后，已创建的 DOM 仍保留。定位非常靠后的匹配时可能需要短暂分批加载。
- 浏览器对连续多文件下载、新标签页的限制与原脚本相同，可能需要用户允许下载。
- 保留原有字幕失配判断、自动选择与批量下载选择逻辑；不同视频的可用语言可能不一致。
